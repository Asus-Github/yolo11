# 大论文研究主线与章节规划

日期：2026-09-21。本文是研究与写作方案，不是已完成实验或已确认原创性的声明。

用户已确认：允许补充公开连续交通视频；导师允许将车辆检测和跟踪计数分别作为两个算法研究方向。

## 1. 总体定位

保留开题题目《基于深度学习的车流量实时检测方法研究》也可以完成这套结构。若允许调整题名，建议《基于深度学习的路侧车辆检测与车流量统计方法研究》。后者更直接体现两部分工作。题目保留“实时”时，需要完整视频处理链路和计数事件确认延迟的实测支持。

研究场景先限定为固定路侧摄像机、单摄像机视角、已设置的道路兴趣区域和有向计数线。不同时拓展到多摄像机重识别、车速估计、交通流预测、拥堵判定和信号控制。

论文主线：路侧图像中的车辆检测 → 视频中的车辆跨帧关联 → 有向通过事件确认 → 按类别、方向和时间窗统计车流量 → 系统验证。

总体研究问题：在路侧远距离目标尺度变化、遮挡和短时漏检条件下，如何实现准确且满足时效要求的车辆流量统计？

- 研究问题一：如何改善作为计数输入的车辆检测结果，降低漏检并提高定位质量？
- 研究问题二：当车辆仍发生短时漏检或轨迹断裂时，如何降低通过事件的漏计和重复计数？

每帧画面中的车辆数量是瞬时在场数量；一个时间窗内穿过指定道路断面的车辆数量才是该时间窗的通过计数。流率可写为 q=N/Δt，并明确使用辆/分钟或辆/小时。不同帧检测框数不能直接相加得到车流量。单凭画面内车辆多也不能证明拥堵。

## 2. 类别口径与小论文的继承

### 2.1 建议的主任务

| 类别 | 大论文角色 |
|---|---|
| Car、Truck、Van、Bus | 主要研究对象，统计汽车总流量及可支持的分车型流量 |
| Cyclist、Motorcyclist | 可选扩展，单列骑行/两轮交通参与者流量，不混入四类汽车结果 |
| Pedestrian | 不计入车辆流量 |
| Trafficcone | 不计入车辆流量；保留原始图像中的真实背景 |

这里选择四类汽车作为主任务是为了明确研究边界，不是说两轮交通参与者不能研究。若最终选择混合交通流，应明确六类任务及两组输出，并让检测、跟踪、计数实验使用一致口径。Cyclist/Motorcyclist 是数据集定义的骑行者类别，不能不经说明当作纯车体类别。

### 2.2 交通锥不使小论文失效，但改变其在大论文中的地位

小论文研究的是“路侧交通小目标检测”，包含交通锥是合理的。它在大论文中作为检测方法的前期技术与实验基础；大论文的车辆结论需要车辆类别上的证据。

不能直接把小论文八类总体 mAP、总体尺度分布或以交通锥为主的可视化改名为“车辆检测结果”。也不需要删除原论文或覆盖历史数据。

对现有逐类结果表进行简单宏平均，可得到：

| 现有八类模型的评价子集 | baseline mAP@0.5:0.95/% | DWCA-P2 mAP@0.5:0.95/% | 差值/百分点 |
|---|---:|---:|---:|
| 四类汽车 | 69.925 | 72.275 | +2.350 |
| 四类汽车加两轮骑行 | 64.783 | 67.533 | +2.750 |

这只是现有八类训练模型的逐类评测结果汇总，来自已舍入的逐类 AP，**不是四类或六类重训实验**，也不是新的测试集评测。四类汽车的 AP50-95 均为正向改进，但 Truck AP50 下降约 2.1 个百分点，说明收益并非每项指标一致。

Trafficcone 占原数据目标实例约 49.10%；标准八类宏平均 mAP 每类等权，不能说交通锥占一半 mAP。原八类总体小目标比例也不能直接用于汽车子集。

### 2.3 两阶段继承方案

先利用现有八类模型，筛选四类汽车预测，验证完整检测、跟踪和计数流程，降低试错成本。

正式检测章节推荐另建四类汽车数据版本，保留所有有效图像及无目标背景图，筛选标注并更新类别配置；在同一新协议下训练 baseline 和 DWCA-P2，再补关键消融。原八类数据、权重和结果保持独立存档。

第一轮关键结构对照可设为 baseline、baseline+P2、+DW、DW-P2、DWCA-P2；是否增加其他消融由拟声称的贡献决定。不需要为了大论文重跑所有失败路线。若最终只保留八类训练，则必须写清“多类交通目标训练、汽车子集评测、汽车流量统计”，不能把它称为四类模型。

## 3. 两个拟定创新点

### 3.1 创新点一：面向车流量统计的路侧多尺度车辆检测方法

技术基础：完整方法使用 DWCA-P2；当前实验记录中的 DWCA 指不含 P2 的消融模型，两者应区分。

小论文提供了检测架构及前期实验。大论文需要围绕车辆尺度变化、漏检和定位质量重新组织论证，补充汽车子集实验、视频检测实验及检测收益向计数收益传递的分析。

待验证假设：高分辨率检测分支及现有特征、回归改进，可改善远端车辆观测，并在相同跟踪计数方法下减少漏计。

贡献表述框架：针对固定路侧图像中车辆尺度差异及远端车辆漏检问题，研究多尺度车辆检测方法，采用 DWCA-P2 作为具体实现，并在车辆检测及后续流量统计任务中验证其有效性。

不能将 DyHead、WIoU、CA、P2 分别列为自己原创的四项算法，也不应把 P2 从已完成小论文中拆出来重复算作大论文第二创新点。当前证据支持 P2 为主要增益来源、CA 为辅助贡献；车辆新实验可能改变这种归因，应服从结果。

### 3.2 创新点二：道路约束与计数事件一致性联合的车辆轨迹关联方法

这是建议推进的研究方向，尚未完成针对性查新、算法实现与效果验证，暂不命名缩写或声称“首次”。

具体问题：车辆在计数线附近被遮挡，遮挡前后被跟踪器赋予不同 ID；前后轨迹片段可能属于同一辆车，但普通计数程序会把它们看成两个对象，或者两段均不足以形成完整穿越证据而漏计。

拟研究一个联合机制，而不是堆叠三个互不相关的模块：

1. 基于道路 ROI、允许行驶方向、时空可达性及类别组一致性，产生可连接的轨迹片段候选。
2. 将片段关联与有向通过事件的证据一起评价，处理仅凭局部框重叠难以确定的遮挡前后对应关系。
3. 保留计数事件状态，使同一次真实穿越在 ID 变化后不会被重复登记；证据不足的事件允许延迟确认或标记不确定。

事件唯一性应按“同一车辆、同一计数线、同一方向、同一次穿越”定义。不能规定一个 ID 永远只计一次，否则掉头、返回或穿过另一条计数线时会漏掉合法事件。

本方向可能采用短窗口轨迹片段图或其他联合优化方式，但具体代价项与求解器应由基线错误诊断决定。道路约束、轨迹片段连接、有限状态机本身均不是当然的新颖技术，需比较已有同类方法后确定差异。

ByteTrack 的高低分检测关联、OC-SORT 的遮挡期间运动修正属于既有工作。简单调阈值、加防抖、延长轨迹缓存或调用现成过线计数，不足以单独支撑创新点。

实时性设计应采用因果处理或有明确上限的延迟确认。若需要未来若干帧，不得仅凭处理 FPS 声称零延迟实时计数；应同时报告视频处理耗时和事件确认延迟，不能读取完整测试视频后再离线优化并称为在线方法。

研究边界：长期完全不可见且缺少足够观测的车辆，不能依靠规则保证恢复；拥挤相似车辆的错误合并风险必须作为对照实验重点。

## 4. 数据集分工

### 4.1 已有 DAIR-V2X-I

当前本地 YOLO 版本为 4940/1411/707 张 train/val/test 图像，共 7058 张，不是开题报告原计划的 19482 张混合数据。原始相机标签有类别、二维框、遮挡与截断状态等；当前本地 metadata 没有明确时间戳、序列 ID，框标签没有 track_id。

适合承担：检测训练与消融、车辆类别与尺度分析、核验标注编码后的遮挡分组分析。不适合直接承担：跨帧 ID 评测和真实车流计数。不能把连续数字文件名视为时间连续的视频。

现有转换脚本按随机图片划分，位置标识在训练、验证和测试中均有出现。因此现有结果不能称为跨路口泛化；这也不等于已经证明存在重复图泄漏。大论文新实验应按实际场景或摄像机设计隔离评测并检查相关帧。

### 4.2 优先核验 V2X-Seq-SPD 路侧图像

已核验官方说明：SPD 路侧 metadata 包含 camera_id、image_timestamp、frame_id、sequence_id，跟踪标注包含 2d_box、track_id；类别包含 Car、Truck、Van、Bus 等，并明确 TrafficCone 无跟踪标注。

它是同系列新增时序数据，不是当前静态 DAIR-V2X-I 自动附带的连续视频。虽然官方基准主要面向协同三维跟踪，本方案只采用路侧图像、二维框和 ID，另建明确的二维车辆跟踪与计数协议，不直接比较官方三维指标。

正式选用前核验：数据访问条件、有效序列长度、帧间隔与缺帧、二维标注覆盖、摄像机稳定性、实际过线事件数量、类别样本数。具有时序标注不等于已经有足够长视频和计数真值。

它与 DAIR-V2X 同源，需要跨数据集核对帧、时间段及场景重叠；若主张跨摄像机泛化，还须隔离摄像机。不能将静态检测预训练集内出现的测试帧用于新的时序测试。

### 4.3 备用或外部验证：UA-DETRAC

作者论文确认包含 100 段真实交通序列以及车辆、遮挡、天气、框等标注，可作为检测与跟踪的外部验证候选。当前旧官网入口存在跳转，具体下载渠道、可用标注和许可仍需核验。

不同数据集的车型体系未必一一对应。可以先比较共同的“车辆”总流量，再在语义一致的类别上评价分车型流量，不能强行将 other 等类别改名为 Truck。

不要求两项创新用完全同一个数据集；要求它们共享研究对象，并通过一套公共视频评测连接起来。

### 4.4 计数真值需另外构建

固定每个场景的 ROI、计数线、方向、目标类别及统计时间窗。利用真值轨迹生成候选通过事件，再人工核验遮挡、进出边界、转弯和重返场景案例。计数真值不能来自待评价模型自身预测。

每个事件至少包括序列、目标身份、类别/类别组、计数线、方向和通过时间；由事件汇总得到时间窗流量。片段较短时按真实持续时间报告计数或流率，不能把不足一分钟的序列结果写成直接观测到的一分钟计数。

视频按完整序列划分开发/验证/测试，避免相邻帧随机分拆。数据量依据独立场景、有效事件数和错误覆盖确定，不能仅用帧数代表证据强度。

## 5. 推荐六章结构

不单独重复设置一个大型综合实验章：第3章和第4章各自包含方法与实验，第5章做完整系统验证。字数比例仅用于控制重点，学校模板优先。

| 章节 | 建议正文比重 | 目的与证据 |
|---|---:|---|
| 第1章 绪论 | 12% | 定义车流量统计需求、检测与跨帧计数两个瓶颈，梳理相关工作并界定贡献 |
| 第2章 相关理论与数据集构建 | 18% | 明确类别、数据划分、检测/跟踪/计数定义和评价协议 |
| 第3章 面向车流量统计的路侧多尺度车辆检测方法 | 25% | DWCA-P2、小论文基础、车辆实验和结构消融，支撑创新点一 |
| 第4章 道路约束与事件一致性联合的车辆跟踪计数方法 | 28% | 待研究关联机制、独立算法对照和组合实验，支撑创新点二 |
| 第5章 车流量实时监测系统设计与验证 | 12% | 完整流程、业务功能和端到端时效验证 |
| 第6章 总结与展望 | 5% | 已验证结论、失败情形和研究边界 |

- 5.4 功能测试、连续运行与端到端时效测试
- 5.5 本章小结

Flask/Vue/MySQL 可承接开题计划，但系统实现不重复计作算法创新。区分瞬时在场数量、时间窗通过计数和流率。实时性测量包含读取、检测、跟踪、计数及适当的输出环节，标明分辨率、设备和并发路数，并报告事件确认延迟。

- 6.3 后续研究方向

摘要和最终创新点表述在关键实验完成后撰写；现在使用“研究/拟设计”的语气，不写尚未验证的精度提升。

## 6. 使两个创新点形成证据链的实验

### 6.1 检测章节

使用同一类别集合、数据协议、输入尺寸、初始化规则和训练预算比较 baseline、DWCA-P2 与关键消融。报告逐类 AP、Recall、模型复杂度和延迟，并明确验证集与测试集用途。至少对关键结论考虑多随机种子稳定性验证。

如果新结果显示主要改善定位、召回增益有限，应如实论证，不预设“检测 AP 提升必然降低流量误差”。

### 6.2 跟踪计数章节的最低组合实验

| 组合 | 检测器 | 跟踪计数方法 | 用途 |
|---|---|---|---|
| A | baseline | 基础方法 | 完整基准 |
| B | DWCA-P2 | 基础方法 | 检测改进的下游效果 |
| C | baseline | 拟研究方法 | 第二方法的独立效果 |
| D | DWCA-P2 | 拟研究方法 | 完整系统效果 |

相同检测器下缓存相同检测结果供不同跟踪计数方法使用；参数仅在开发/验证视频上选择。这样才能区分“检测更好”与“关联计数方法更好”。

比较至少包含 ByteTrack+统一基础计数器、一个有代表性的其他跟踪器（如 OC-SORT）+相同计数器，以及简单延长缓存/轨迹平滑等对照。对拟研究方法移除道路约束、移除事件一致性约束，并评价两者组合是否优于单项。

### 6.3 指标与评价边界

- 检测：车辆 mAP、Recall、逐类结果、误检/漏检样例。
- 跟踪：IDF1、HOTA、ID 切换和轨迹碎片等，须具备真值 ID。
- 计数：按方向和时间窗的 MAE、RMSE，可用 WAPE；同时报告事件级 Precision/Recall/F1、重复计数和漏计，避免总数误差抵消。
- 零流量窗口保留评价；MAPE 存在零分母，不宜不加说明作为主指标。WAPE 在整组真值总数为零时也需单独处理。
- 时效：完整流水线 FPS/耗时和事件确认延迟，不能仅用检测网络 FPS 代表系统。

不要把大量高度相关的相邻帧当作大量独立样本。按视频/摄像机场景报告结果分布，针对密集遮挡、停车再启动、转弯/重返及同类近邻误合并分析边界。
